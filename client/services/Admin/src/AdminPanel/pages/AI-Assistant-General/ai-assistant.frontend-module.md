# AI-ASSISTANT FRONT-END MODULE CONTEXT

## 1. System Overview

- AI Assistant — это отдельный домен внутри существующего проекта (NestJS + MongoDB + DDD + UseCase).

- Цель модуля:
→ предоставить инфраструктуру для работы с AI-моделями
→ а не просто чат

- Ключевая концепция:

→ Orchestrator (оркестратор)

## 2. Distributed Orchestrator

- Оркестратор — это слой, который:

- принимает запросы от Controllers
- выбирает модель по дефолту если не указана
- выбирает модель если указана
- выбирает провайдера по дефолту если не указан
- выбирает провайдера если указан
- срабытывает FalBack при отвале интернета и переключается на локальную модель
- выбирает ноду (машину ПК) если указана
- выбирает ноду (машину ПК) по дефолту если не указана

- управляет выполнением inference
- абстрагирует систему от конкретных AI-провайдеров

## 3. Responsibilities
Оркестратор отвечает за:

управление контекстом (History Chat prompts)
управление контекстом (System Prompts)

управление стеком знаний knowledge (не доделано!!!)
управление обновлением стека знаний knowledge (не доделано!!!)

## 4. High-Level Components
## 4.1 Orchestrator Core

Центральная точка принятия решений внутри AI Assistant.

Отвечает за:

обработку входящего запроса из UseCase слоя

выбор стратегии выполнения inference
координацию между модулями (routing, context, execution)
изоляцию бизнес-логики от AI-инфраструктуры

## 4.2 Execution Layer (Inference Layer)

Слой выполнения запросов к AI.

Отвечает за:

отправку запроса на выбранную ноду
вызов локальной модели (Ollama)
вызов внешних провайдеров (если подключены)
получение ответа от модели
возврат результата обратно в Orchestrator

## 4.3 Routing System

Логика выбора пути выполнения запроса.

Включает:

выбор модели (если не передана — берётся дефолт)
выбор провайдера (локальный / внешний / fallback)
выбор ноды выполнения (по дефолту или явно указанной)
обработку fallback-сценариев при недоступности

## 4.4 Node Management Layer

Управление машинами (нодами), на которых выполняются модели.

Отвечает за:

регистрацию нод в системе
хранение статуса ноды (online / offline)
контроль доступных моделей на каждой ноде
мониторинг доступности выполнения inference
подготовку информации для routing слоя

## 4.5 Model Management Layer

Управление списком и характеристиками моделей.

Отвечает за:

хранение списка доступных моделей
тип модели (chat / embeddings / etc.)
ограничения моделей (контекст, нагрузка)
связь модель ↔ ноды
выбор подходящей модели по запросу

##  4.6 Context Manager

Слой работы с контекстом диалога.

Отвечает за:

сбор History Chat prompts
добавление System Prompts
подготовку финального prompt
управление длиной контекста
базовое trimming (обрезка истории при переполнении)

## 5. Current Implementation (FACT)
## 5.1 DDD Integration

модуль встроен в существующий backend
используется UseCase архитектура
нет прямых вызовов моделей из контроллеров 

## 5.2 Domain Separation

AI Assistant отделён от Chat
не использует chat как доменную основу
является отдельным bounded context

## 5.3 Admin Integration

модуль находится в админ-панели
планируется управление:
моделями
нодами
запросами

## 7. Key Architectural Decisions
## 7.1 Orchestrator Inside Backend

Orchestrator не выделен в отдельный сервис

→ живёт внутри NestJS монолита
→ управляется через UseCase слой
→ не имеет прямой зависимости от UI или внешних клиентов
