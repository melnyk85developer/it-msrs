# CURRENT PROJECT MISSION (GLOBAL)

## 1. Core Objective

Создать FullStack-приложение (Backend + Frontend) уровня production,
которое соответствует требованиям рынка (middle+/senior уровень):

- чистая архитектура (DDD на backend)
- предсказуемое взаимодействие frontend ↔ backend
- масштабируемость
- тестируемость
- отсутствие костылей
- готовность к реальной эксплуатации

---

## 2. Architectural Direction

Проект разрабатывается как FullStack система:

### Backend:
- NestJS
- DDD (Domain-Driven Design)
- UseCase-ориентированная бизнес-логика

### Frontend:
- React
- Redux Toolkit
- TypeScript

Принцип:
→ frontend НЕ существует отдельно  
→ frontend работает строго через backend API  
→ архитектурные решения backend напрямую влияют на frontend

См.:
→ it-mars.project.context.md (реализация и ограничения)

---

## 3. Functional Domains (Target State)

Ниже описано, что должно быть реализовано в системе в итоговом состоянии.

---

### 3.1 User / Profile Domain

Backend:
- управление профилем
- хранение данных пользователя
- работа с аватарами

Frontend:
- отображение профиля
- редактирование
- работа с UI галереи

---

### 3.2 Posts Domain

Backend:
- создание и хранение постов
- работа с изображениями

Frontend:
- отображение постов
- UI карусели
- взаимодействие пользователя с постами

---

### 3.3 Blogs Domain

Backend:
- управление блогами
- структура блог → пост

Frontend:
- отображение блогов
- навигация
- UI взаимодействие

---

### 3.4 Messages Domain

Backend:
- отправка и хранение сообщений
- логика удаления (у себя / у всех)

Frontend:
- UI чата
- синхронизация сообщений
- отображение состояний

---

### 3.5 File Management Domain

Backend:
- загрузка файлов
- хранение (avatars, post-images)
- корректные пути

Frontend:
- загрузка файлов
- предпросмотр
- crop / compression

---

### 3.6 Bots / Automation Domain (Extended)

Backend:
- генерация пользователей
- генерация постов
- генерация данных

Frontend:
- UI генератора
- управление процессом генерации

---

### 3.7 AI Integration Domain (Extended)

Backend:
- интеграция AI
- работа с локальными моделями
- оркестрация запросов

Frontend:
- UI взаимодействия с AI (чат, админка)
- отображение ответов
- управление запросами

---

## 4. System Qualities (Non-Functional Requirements)

Система должна обеспечивать:

- согласованность frontend ↔ backend
- расширяемость
- читаемость кода
- предсказуемость поведения
- отсутствие скрытой логики

---

## 5. Development Strategy

Разработка ведется по принципу:

1. Реализация доменов
2. Выравнивание backend ↔ frontend
3. Приведение к DDD (backend)
4. Устранение архитектурных нарушений
5. Интеграция в единую систему
